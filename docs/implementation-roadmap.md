# tmux-borrow — implementation roadmap

A chronological build plan, from empty repo to release, with a test for every step and a Make target to run it. Each step is small enough to implement and verify in one sitting; later steps depend only on earlier ones.

The spec is `docs/tmux-borrow-requirements.md`. Read it before starting; this roadmap implements it, it does not restate it.

---

## Conventions

- **Language:** Bash for everything; short Perl/awk helpers only where they materially simplify parsing. No Python in runtime code. Test scripts are Bash.
- **Single file, one dispatcher.** All runtime code lives in **`bin/tum`** — every command is a small bash function (`cmd_borrow`, `cmd_new`, …) grouped with its helpers, and a `case` dispatcher at the bottom routes `tum <cmd> …` to the right function. Commands are kept short on purpose: a function that grows past ~40 lines is a signal to factor helpers out, **not** to split the file. The only code that lives outside `bin/tum` is `scripts/tum-chooser` (an external fzf wrapper invoked by contract) and the static `scripts/tum-bindings.conf`.
- **Complete help, every command.** Every `tum <cmd>` accepts `-h`/`--help` and prints a short usage (synopsis + examples). `tum` with no args, or `tum --help`, lists every subcommand with a one-line summary. The short help is **extracted from the command's manpage source** (`man/tum-<cmd>.1.md`) by `tum_help <cmd>` — one source of truth, no drift between help and manpage.
- **Manpage per command, generated from markdown.** `man/` holds markdown sources (`tum.1.md`, one `tum-<cmd>.1.md` per subcommand, `tum-defs.5.md`, `tum-keymap.5.md`). `make man` renders them to `man/*.1`/`*.5` with pandoc (`pandoc -s -t man`); if pandoc is absent a bundled `scripts/md2man.awk` handles the subset we use (headings, lists, fenced code). Generated files are gitignored; the markdown is canonical. `make install` installs them to `$(MANDIR)`.
- **Tests run against a private tmux server** on socket `tum-test` (`tmux -L tum-test -f /dev/null`), never the user's default server. The harness (`t/lib/harness.sh`) wraps every test tmux call through `tum_t`. Runtime code's own wrapper `_tm` honors `TUM_SOCKET`/`TUM_TMUX`, so tests point runtime functions at the test server by exporting `TUM_SOCKET=tum-test`.
- **One test per step**, at `t/steps/<NN-name>.sh`. It sources `t/lib/assert.sh` + `t/lib/harness.sh`, calls `plan()`, asserts, and the EXIT trap reports pass/fail. `t/run.sh <id>` dispatches; a missing script prints `PENDING` and exits 0, so `make test` is green from day one and steps flip from PENDING to PASS as you go.
- **Make targets:** `make test-NN-name` (one step), `make test-phaseN` (a phase), `make test` (all), `make viability` (R1 — done), `make man` (render manpages), `make install`, `make server`/`server-kill`, `make clean`.

## Help system & manpages

- **Short help (`-h`/`--help`).** Every `cmd_*` handles `--help`/`-h` by calling `tum_help <cmd>`, which extracts the **SYNOPSIS** and **EXAMPLES** sections from `man/tum-<cmd>.1.md` with awk and prints them. If the markdown is absent (e.g. `bin/tum` run before `make man` on a bare checkout), a minimal hardcoded fallback is printed. `tum` with no args / `tum --help` lists every subcommand one-per-line with a one-line summary, read from `man/tum.1.md`.
- **Manpages.** One per subcommand (`tum-<cmd>.1`), plus `tum.1` (overview + subcommand index + common options), `tum-defs.5` (the `.util`/`.layout` file format with a full example), and `tum-keymap.5` (the complete keymap reference). Every page has: NAME, SYNOPSIS, DESCRIPTION, OPTIONS, **EXAMPLES** (≥2 real invocations), SEE ALSO.
- **Generation.** `make man` renders `man/*.md` → `man/*.1`/`*.5`. Primary renderer: `pandoc -s -t man man/<name>.md -o man/<name>.<sec>`. Fallback when pandoc is missing: `awk -f scripts/md2man.awk man/<name>.md > man/<name>.<sec>` (handles `#`/`##` headings, bullet lists, and fenced code blocks — the whole subset our sources use).
- **Install.** `make install` copies `bin/tum` → `$(BINDIR)`, `scripts/tum-chooser` + `tum-bindings.conf` + `tum-completion.bash` to their dirs, and every generated `man/*.1`/`*.5` → `$(MANDIR)`.

## Phase 2 — borrow (the spine)

Every command step in this phase **ships `tum <cmd> --help` and `man/tum-<cmd>.1.md`** (synopsis + ≥2 examples, rendered by `make man`).

### 2.1 — Create + attach (`tum borrow <util>`, create branch)
- **Build:** `cmd_borrow` with no reusable instance: `tum_validate` (command exists + executable); `_tm_split` a pane beside the host; `tum_state_set` `util/host/home=/slot=<auto>/src=defined`; auto-assign a slot unique within the host window.
- **Test (`04-borrow-create`):** from a host pane, `tum borrow simple` attaches a pane beside it; state `util=simple`, `host=<host>`, `home=` (pool), non-empty `slot`, `src=defined`; pane alive running `htop`.
- **Make:** `make test-04-borrow-create`

### 2.2 — Reuse a hidden instance bound to this host
- **Build:** `tum_resolve` step 1 — if an instance with `host=<current>` exists, borrow it (already bound; a show/no-op move).
- **Test (`05-borrow-reuse-host`):** borrow `simple`, hide it (flip, once 3.1 lands — or move to hidden session here), then `tum borrow simple` from the same host brings the same pane id back.
- **Make:** `make test-05-borrow-reuse-host`

### 2.3 — Reuse a hidden pool instance
- **Build:** `tum_resolve` step 2 — if hidden pool instances exist, borrow one (chooser if several). Until the chooser ships (6.1), numbered-list / first-match fallback.
- **Test (`06-borrow-pool`):** create a pool `simple` from host A, hide it; from host B, `tum borrow simple` brings that hidden pool instance (state `host`→B, `home` stays empty).
- **Make:** `make test-06-borrow-pool`

### 2.4 — `tum new` (owned instance)
- **Build:** `cmd_new` — always-create; `home=<current>`; the instance is owned. Flip-flop (3.1) returns it only to `home`.
- **Test (`07-new-owned`):** `tum new simple` from host A sets `home=<A>`; hide it; from host B, `tum borrow simple` does NOT take it (denied — create another or pick via chooser); from host A, re-borrow returns it. Assert the stealing table's owned rows.
- **Make:** `make test-07-new-owned`

### 2.5 — No-name `tum borrow` (chooser)
- **Build:** `cmd_borrow` with no argument opens the chooser over all utilities and layouts; uninstantiated picks create+borrow, instantiated picks borrow that instance. Uses the chooser contract; until 6.1, numbered-list fallback.
- **Test (`08-borrow-noname`):** with `simple` and `log-tail` defined and no instances, no-name borrow lists both; picking `simple` creates+borrows. With an existing hidden `simple`, the list shows it and picking it borrows the existing one.
- **Make:** `make test-08-borrow-noname`

### 2.6 — Input prompting + placeholder substitution
- **Build:** `tum_prompt_inputs` — at create time, prompt for every `input` in declaration order before any tmux mutation; substitute answers into `{{name}}` tokens in `args`, `cwd`, `command` only (env values are static, never substituted). If stdin is not a TTY (non-interactive), fail with the missing input names instead of hanging.
- **Test (`09-input`):** `tum new log-tail` with stdin fed `/var/log/syslog` produces a pane running `tail -n 200 -f /var/log/syslog` from cwd `/var/log`; a second `tum borrow log-tail` (reuse) does not prompt; non-interactive create with no stdin fails with `missing input: file`.
- **Make:** `make test-09-input`

### 2.7 — Environment variables + `use-process-env`
- **Build:** `tum_apply_env` — at launch the process inherits the calling environment, then the file's env keys are applied on top. If `use-process-env: yes`, for each env key that also exists in the calling environment, override the file value with the process value. (R2 accepted: special/env keys are environment variables, overridden on load.)
- **Test (`10-env`):** a fixture with `FOO: fileval` and no `use-process-env` launches with `FOO=fileval` even if the caller exports `FOO=shellval`; with `use-process-env: yes` and `FOO=shellval` exported, the pane sees `FOO=shellval`; with `use-process-env: yes` and `FOO` not exported, `FOO=fileval`. Verify by having the launched command print the var.
- **Make:** `make test-10-env`

### 2.8 — Safe argv (no eval)
- **Build:** `tum_argv` — build the argv array from `command` + tokenized `args`, preserving boundaries, no `eval`/`sh -c`. The tokenization rule is open item R3 — decide it from `examples/full-demo.util`'s args-variants block, implement here, and write the rule into the spec's Safe-argv section.
- **Test (`11-argv`):** assert argument boundaries for the cases you settle on from the variants block (at minimum: multiple tokens, a quoted span, a `{{placeholder}}` expanding to a value with spaces). Verify by launching a utility that echoes its argv (`printf '%s\n' "$@"`) and checking the output lines.
- **Make:** `make test-11-argv`

### 2.9 — Command validation
- **Build:** `tum_validate` — before borrow, check `command` exists and is executable (PATH lookup or absolute path); fail with a clear message instead of launching a pane that dies at once. A key that is not a special key and not a valid variable name is a parse error (R2: a valid-name typo becomes an env var, accepted).
- **Test (`12-validate`):** a `.util` with `command: nonexistent-tool-xyz` fails borrow with a message naming the command and exits non-zero; no pane created; a valid command succeeds.
- **Make:** `make test-12-validate`

## Phase 3 — flip-flop, hide, close

### 3.1 — `tum flip <slot>` (hide/show) + geometry
- **Build:** `cmd_flip <slot>` toggles the slot's bound thing: shown → `_tm_move` to the hidden session, clear `host`, `tum_geom_capture` (`geom=WxH`); hidden → bring back beside its host (owned: only its `home`; pool: its last host or a new one per resolution), `tum_geom_restore`. A layout's slot toggles all members as a group (N8). **Help:** `tum flip --help` + `man/tum-flip.1.md`.
- **Test (`13-flip-slot`):** borrow `simple` at slot 1; flip → hidden session, `host` empty, `geom` set; flip → back beside host, `geom` restored. For an owned utility, flipping from a non-home host does nothing to it.
- **Make:** `make test-13-flip-slot`

### 3.2 — `tum flip` (context-aware, via `tum_target`)
- **Build:** `tum_target` resolver in the state group: focused borrowed pane → host's single borrowed thing → chooser when the host has several → nothing. `cmd_flip` with no slot uses it.
- **Test (`14-flip-context`):** from a focused borrowed pane, flip toggles just it; from a host with one borrowed thing, flip toggles that; from a host with several, flip opens the chooser.
- **Make:** `make test-14-flip-context`

### 3.3 — `tum close` (context-aware kill-pane)
- **Build:** `cmd_close` — `_tm_kill` the `tum_target` selection. No confirmation. State dies with the pane. **Help:** `tum close --help` + `man/tum-close.1.md`.
- **Test (`15-close`):** close a focused borrowed pane → gone from `list-panes -a`; close from a host with one borrowed thing → that thing gone; close from a host with several → chooser-pick gone; survivors' state unchanged.
- **Make:** `make test-15-close`

### 3.4 — Geometry is captured only on tum commands (N5)
- **Build:** nothing new — a property to verify: no background process watches pane sizes. `geom` is written only at hide/push and read at show/pop.
- **Test (`16-geometry`):** borrow `simple`; resize its pane live; `geom` unchanged (no capture); flip (hide) → `geom` reflects the resized size; flip (show) → restores it. Resize again while shown, then push → `geom` reflects the latest size; pop → restores it.
- **Make:** `make test-16-geometry`

## Phase 4 — push/pop, import, ls, check

### 4.1 — `tum push` / `tum pop`
- **Build:** `cmd_push` detaches the focused borrowed pane (or `tum_target`) onto a LIFO stack: `tum_geom_capture` + assign `push=<seq>`, clear `host`. `cmd_pop` attaches the highest-`push` pane to the current host at its recorded geom, consuming it. Push/pop is independent of pool/owned (N4): `home` untouched; a pushed pane is not reachable by `tum flip`. **Help:** `tum push --help`, `tum pop --help` + `man/tum-push.1.md`/`man/tum-pop.1.md`.
- **Test (`17-push-pop`):** push `simple` from host A (`push=1`, loses `host`); from host B, `tum pop` attaches it at the recorded geom; `tum flip` does not find it while pushed. Push two, pop twice → LIFO order.
- **Make:** `make test-17-push-pop`

### 4.2 — `tum import` (anonymous + named)
- **Build:** `cmd_import` — anon: mark the current pane a temporary utility (`src=imported-anon`, `util=import-<pane-id>`, no file). named: capture command/args/cwd/env from `/proc/$pid/` at max fidelity and write `<name>.util` (`src=imported-named`). **Help:** `tum import --help` + `man/tum-import.1.md`.
- **Test (`18-import`):** in a pane running `vim`, `tum import` marks it `src=imported-anon` and it appears in `tum ls`; `tum import editor` writes `~/.config/tum/editor.util` with the captured command/cwd/env and marks `src=imported-named`.
- **Make:** `make test-18-import`

### 4.3 — `tum ls`
- **Build:** `cmd_ls` — list all utility panes across sessions from `list-panes -a`, columns Utility / Layout / Host / Home / Slot / Geometry / State (shown, hidden, pushed, orphan). **Help:** `tum ls --help` + `man/tum-ls.1.md`.
- **Test (`19-ls`):** with a shown pool utility, a hidden owned utility, and a pushed pane, each appears with the right state label and host/home fields.
- **Make:** `make test-19-ls`

### 4.4 — `tum check` (orphans)
- **Build:** `cmd_check` — lazy: list panes whose `host` points at a dead pane id (not in `list-panes -a`), marked `!`. No auto-action. **Help:** `tum check --help` + `man/tum-check.1.md`.
- **Test (`20-check`):** borrow `simple` from host A; kill host A's pane; `tum check` lists `simple` as an orphan (`host gone`); re-borrowing it from host B clears the dead binding.
- **Make:** `make test-20-check`

## Phase 5 — layouts

### 5.1 — layout DSL parser (in `tum_defs_*`)
- **Build:** extend `tum_defs_parse` for `.layout` files: `layout_id` and `focus` are the only special keys; every other key is a member entry `<member>: anchor=…, side=…, size=…`. Same `while IFS=: read` loop as utilities.
- **Test (`21-layout-parse`):** parse a fixture layout; assert `layout_id`, `focus`, each member's anchor/side/size; `anchor` defaults to `host` when omitted; `side` required (error if missing).
- **Make:** `make test-21-layout-parse`

### 5.2 — Borrow a layout (members attach)
- **Build:** `cmd_borrow <layout>` resolves all member definitions and `input`s before any tmux mutation, then adds member panes incrementally beside the host and anchoring members. Each member gets its own slot; the group gets a slot. Never apply a whole-window `select-layout` that would resize ordinary panes.
- **Test (`22-layout-borrow`):** borrow a 3-member layout; all members at their declared positions; each member state has `lay=<layout_id>` and a distinct slot; the group slot is set.
- **Make:** `make test-22-layout-borrow`

### 5.3 — Member anchoring
- **Build:** a member may anchor to another member (not just the host), allowing two panes on the same side.
- **Test (`23-layout-anchor`):** a layout with `editor: anchor=host, side=right` and `logs: anchor=editor, side=bottom` places logs below editor, both off the host's right.
- **Make:** `make test-23-layout-anchor`

### 5.4 — `focus` + group flip-flop (N8, N9)
- **Build:** on borrow, focus the member named by `focus` (or the host, the default — N9: `host` is a no-op since borrowing leaves you on the host). Group flip-flop acts on ALL members (N8): group hide hides every member; group show shows every member, including any individually-hidden one.
- **Test (`24-layout-focus`):** borrowing a layout with `focus: editor` leaves `editor` focused; with `focus: host` (or omitted) the host stays focused. Individually hide one member, then group-hide → all hidden; group-show → all shown (the individually-hidden one comes back too).
- **Make:** `make test-24-layout-focus`

## How to run

```sh
make viability          # R1: state-store test (done; Alternative A chosen)
make man                # render man/*.md → man/*.1 / *.5 (pandoc, or scripts/md2man.awk)
make server             # start the private test server
make test               # run every step (PENDING steps print and pass)
make test-phase1        # run one phase
make test-11-argv       # run one step
make install            # install bin/tum, scripts/, and manpages
make server-kill        # stop the test server
make clean              # stop server + drop temp files
```

A step goes from `PENDING` to `PASS` when you create `t/steps/<NN-name>.sh` and the functions it tests. `t/steps/01-defs.sh` shows the pattern (parse + dispatcher + help + `make man`).
